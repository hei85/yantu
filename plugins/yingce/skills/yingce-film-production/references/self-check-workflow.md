# 图片、视频与整片自检

用于从剧本自动制作、接续和工作流审计。先区分“实际媒体能读”“内容合格”“正式采用”“成片交付”；任务成功、安装插件、深度图、ASR 命中或没有审美问题，不能代替后面的结论。

## 1. 接管后先查真实状态

读取 `runtime_diagnostics`、目标画布与当前 `film_get_run`，再调用 `film_self_check`。传真实 canvasId/runId，默认检查 20 个资源，可按 nodeIds 分批；最多 120 个资源完整解码。检查返回的 omittedResourceIds，不能把未探测的资源写成通过。

该入口是只读审计：实际资源解码、版本匹配、正式步骤完成情况、既有逐项内容证据、声音听审及插件报告。它输出待检查队列，不提交生成、不替 Agent 看图听音，也不自动写入通过。查询或解码故障只表示可用性检查失败，不证明上游生成终止。

Agent 自主处理队列：取得实际媒体 → 检查 → 定位失败 → 修复受影响部分 → 复查 → 正式登记。已有用户采用的素材继续保留；旧证据不完整时补查，不能为了新规则重生成已采用图片。后续新项目使用最新规则，运行中锁定的技能/输入版本保留。

## 2. 每张图片都查，母图和切图分别查

- 读取实际原图并放大必要区域。基础身份、场景、道具分别检查；真人身份采用同一张已确认身份及所需三视图，不能只凭名字认定同一人。
- 四宫格逐格检查身份、服装、手指/四肢、工具数量、关键动作、空间和道具。四格是同一镜头的四个关键时刻，不是四个独立房间；不能用一格合格代表整张合格。
- 切分后逐张看：没有边框、分割线、邻格残留或裁掉必要部位；每格都能独立读取，画布不叠放。保存实际 nodeId/resourceId、对应镜头、时间状态和具体观察。
- 首帧采用本镜独立切图1。前镜第4图传递人物、空间、道具和动作状态；后镜第一关键时刻必须推进动作，不能完全复刻前镜末格。普通引用的第4图不是渠道保证的严格尾帧。
- 近景正常出画/遮挡与物体消失要区分。原应可见的椅子、收音机、水杯等缺失，或者承托物/材质改变，记失败；正常出画注明原因。
- 提交前回读真实引用及输入顺序：智能 @ 内联绑定稳定节点，每张图有明确用途；独立切图不能换成母图，重复资源去重，最多数量以当前渠道实测能力为准。六图方案是本片采用方式，不是所有模型固定要求。

## 3. 空间、距离和方向

封闭室内先按 [固定空间流程](fixed-space-workflow.md) 做房型图、同一共用模型、固定机位及取景，再生成关键图和视频。户外不强制此准备。计划记录世界坐标、开口连接、物体尺寸、机位位置/目标/镜头、人物路线及移动前后状态。

检查同一模型源/哈希或真实 DirectorScene、相机版本与真实渲染资源，随后对照实际生成画面；只给几张不同机位 AI 图不能称作已建立共用模型。门洞大小和位置不变，洗手台与出口的相对位置不因换机位改变。人物身体朝向、头部朝向、视线和移动方向分别检查，路径实际经过既定门洞。

人物与桌子间距只有真实走位或物体移动才能变化，不能因为换焦段就从5米变10米。米数检查用同一世界坐标与测量锚点；未标定照片、单目深度和姿态图不能证明精确距离。详见 [距离与状态台账](spatial-distance-continuity.md)。

## 4. 视频查实际动作，衔接查实际首尾

每个实际片段完整解码，提取首帧、关键动作前/中/后、说话期间和末帧。正式逐镜合同至少5个不同实际时刻，这只是证据下限；转身、撞击、跨门、反射、手持道具等异常风险必须增加采样，不能按五张样本声称看过全段。

按镜头目标核对：一个人物的不同时刻不得变成复制人物；动作顺序和接触时间正确；相机运动、景别、距离、视线合理；房间家具和工具固定；没有瞬移、穿墙、奇怪切屏或将四张图当幻灯片。复杂动作可逐帧审查相关区间。

按故事顺序比较前镜真实末态、过渡真实起止和后镜真实首态。已通过的图片不保证视频仍通过。过渡分配到明确片段和时间线采用区间；剧情有意跳时/跳地点可直接剪切，连续跨相邻空间则用确实交代路径的镜头。

## 5. 声音独立检查

核对原句、说话人、实际说话区间和词尾；对白优先放中段，留开头承接及结尾反应。ASR 只辅助文字与时段，音轨存在/解码成功不证明声线、噪声、爆音、配乐、口型或对白完整。

只有具备听音能力的实际评估者检查了原音轨，才记录 listeningStatus=performed、voiceQuality 与 evaluator/summary；未听到就记 not_performed/uncertain。口型还需要同时间画面证据。无声项目按实际合同免除听审；有声项目在样片阶段识别可用听审路径，缺少路径先继续独立可执行工作，但最终音频质量不能放行。

剪掉用户要求移除的无关声音，保留合规对白和所需环境声。原生声音默认保留；重新配音需要用户已有授权和实际声音绑定。音乐按剧情连续、自然进出，不能逐镜随意重启。

## 6. 新 MCP 工具参与定位和修复

| 检查发现 | 实际工具与复查 |
| --- | --- |
| 身份/手部/局部错误 | Agent 放大原图；`canvas_preflight_image_edit` → `canvas_edit_image` 的真实蒙版/表情操作，检查新的结果和其连续性 |
| 姿态、遮挡或几何可疑 | 按能力调用 `canvas_convert_media` 的姿态/深度输出，结合固定模型和原图定位；派生图不代替质量结论 |
| 文字、光影或材质错误 | 真实文字检测/反推提示词与 `canvas_edit_image` 文字、打光、质感；修改进入原生提示词，保留正确区域 |
| 透明边缘或独立层错误 | `canvas_convert_media` 本地去背景，或有授权的透明编辑/图层拆分；查实际 alpha、主体、边缘、画幅和位置 |
| 已有审美/肖像分析 | `canvas_read_quality_reports` 读取实际报告/taskId。源图变化即失效；报告仅覆盖其检查范围，不充当影片整体通过 |
| 视频动作、衔接或声音错误 | `canvas_extract_video_frames` / `canvas_extract_video_audio` 与实际评估，配合时间线/ffmpeg 修剪或局部修复；再次检查实际导出 |

工具参数从当前目录/schema读取，详细方法见 [图片工具与 MCP](image-toolbar-tools.md)。只读预检、报告读取和派生诊断可先做；收费修图沿用当前授权、预算和能力。未提供的插件执行入口不能编造，也不能绕过其原生批准流程。

## 7. 失败原因进入修复与提示词

每次记录镜头/资源/输入版本、实际时刻或图上区域、观察到的症状、应有状态、原因的证据或“原因未知”、修复方法和结果。区分参考错绑、提示词歧义、模型能力、空间计划、任务/网页显示与剪辑问题；不能统一归因于提示词。

下一版提示词写清参考用途、正确关系与具体动作，再把仍未解决的失败形态写入对应段落。例：收音机继续由原木桌承托；人物转向既定出口并跨过唯一门洞；同一人镜内静态头肩不能同步抬工具。错误状态不得作为后镜参考。

同一输入连续出现同一内容问题时停止盲目重复长负面提示词，评估更清晰参考、局部修图、改变可行镜头设计或剪辑修复。每次修改保存新输入和真实 retryOf；运行中的原请求只查询、不重复计费。无法判断或尚未解决的项记 uncertain/failed，并阻止其依赖正式采用。

## 8. 正式证据与放行

新 `film_create_run` 计划构建器默认生成 selfCheckVersion=1 和 selfCheckContracts；读取返回合同，不自行省略媒体或抽帧要求。旧运行不会为规则升级而改变指纹。服务器从合同的 resourceIds 和 sourceStepKeys 成功输出获取真实资源，校验所有权、当前输入指纹、逐资源检查、不同采样时刻及必要听审。

记录 `film_record_step_result` 时，除原阶段/技能证据外提供：

```json
{
  "inputFingerprint": "从当前步骤读取",
  "checks": [{"name": "逐镜内容", "status": "passed", "detail": "实际观察摘要"}],
  "semanticQuality": {"status": "passed", "model": "实际评估者", "summary": "实际观察结论"},
  "reviewedMedia": [{
    "resourceId": "合同绑定的真实输出资源",
    "checks": [{"name": "合同要求的检查项", "status": "passed", "observation": "该资源的具体观察"}],
    "samples": [{"timeMs": 0, "observation": "该实际时刻的画面；其余所需样本另列"}],
    "audioReview": {"listeningStatus": "performed", "voiceQuality": "passed", "evaluator": "实际听审者", "summary": "原音轨检查意见"}
  }]
}
```

示例只是字段形状，数量、检查项和实际值从合同/媒体取得，不能复制假值。漏资源、漏项、重复样本、缺末态、未听审或无具体观察保持 uncertain；错绑定/旧指纹拒绝；已发现 failed 不能被别处未验证覆盖。资源、提示词或剪辑版本改变后复核受影响证据。

## 9. 最终交付自检

对真实最终文件完整解码并按故事顺序检查全片：剧情覆盖、采用区间、所有必要过渡、首尾与镜头节奏、黑帧/闪烁/异常冻结、音画同步、对白和混音、字幕策略、实际帧数/长度/画幅。具体长度按用户最新要求；变更合同要有真实版本，不能拿早期固定180秒误判后来许可的约3分钟剪辑。

把实际导出资源、文件哈希、时间线版本及内容证据写回正式运行，核验输出节点播放和媒体存储。`film_self_check` 的资源队列清零只是必要条件；正式阶段和整片实际质量均通过后才交付为完成。整理受影响区域并回读；全画布重排仅在用户要求时执行。

未来使用者给出剧本且模型/费用授权齐备，Agent 按此闭环自主完成普通决定与返工，不要求逐镜手把手指导。模型和外部渠道仍可能失败，未验证内容必须可追溯，不能承诺仅靠规则永远一次成功。
