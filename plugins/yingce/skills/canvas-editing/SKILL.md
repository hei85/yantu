# 可靠编辑

## 写入和回读

明确目标节点 ID、rowId 与修改字段。用新上下文取得 `expectedCanvasId`、`expectedRevision`、`expectedStateHash`；只刷新版本可读 summary。局部节点读取的完整文本可用来修改提示词，截断预览不能覆盖原文。

节点、连线或顺序有依赖的批量编辑先用 `canvas_validate_ops` 校验，依赖变更在同一批内明确引用。写入串行执行；读操作可并行。不要把创建/移动/删除与收费生成混进同一批。写后按目标回读节点、行、连接和资源；批量报错先确认哪些操作已经生效，不假定全部未执行。版本冲突先重读、比较用户改动，再重新计算修改。

创建使用 `canvas_create_node` 的真实页面类型；分镜和逐行输出使用对应专用工具。Frame、文件夹、上传、替换媒体均用原生工具，不用任意 metadata 假造保存或完成。保留节点 ID、采用 resourceId 和用户手工关联。

## 引用与生成

用 `canvas_edit_reference` 的 add/remove/replace/reorder 维护明确节点引用；分镜行使用 `canvas_update_storyboard` 的真实资产绑定。引用改动不会提交生成。回读核对真实资源去重、参考编号/顺序、角色用途、可见连线与 composerContent 内联智能 `@`。纯文字“@图片1”不是绑定证明；正文直接写在目标生成框，避免额外文本节点和无用连线。

视频按对应分镜行继承采用资产和本镜首帧；生图直接引用所需图片。使用独立切图，不用四宫格母图代替首帧或视频参考。前镜末格只传连续状态，下镜必须推进动作；详细制作要求见相关制作技能。参考图上限与严格首尾帧支持由当前渠道能力决定，不能把某次六图方案推广到所有模型。

生成先调用对应 preflight，核对模型、参数、实发媒体输入及已有授权。已提交或回执不确定先查原 taskId/clientOperationId；原请求恢复沿用 ID。明确终止失败且已有重试授权时建立有 retryOf 的新尝试，把具体失败原因和正确动作加入提示词。运行中不重发；批次记录每行的成功、失败和未提交状态，并发按用户最新要求与实际渠道限制执行。

## 布局、清理与撤销

每批创作后检查整张画布是否清楚，局部整理本次相关节点。`canvas_layout_nodes` 明确传 ids；省略 ids 会优先选区，没有选区会作用全图，`ids=[]` 明确作用全图。用户要求整体整理时才使用全图范围。保留既有分区、镜头顺序、容器、锁定内容和手工排列；Frame 布局可能带动子节点，先读范围。切图和视频逐个可见，不重叠，标题写清镜头与阶段，文档放文档区。

清理已授权的失败/无用节点前检查采用资源、分镜/时间线引用和真实任务状态。不得把正在生成或下游仍使用的节点当作垃圾；保留有用途的历史证据后清理其占位节点和无效连线。优先修正现有节点，避免重复复制素材。

撤销用 `canvas_undo_agent_ops` 的原生历史；它只适用于未被用户操作打断的最近 Agent 操作。失败先读状态，不伪造反向操作覆盖用户编辑。完成后回读真实结果和布局；“工具已调用”不等于保存完成或质量通过。

## 专用编辑

使用图片节点截图中的局部重绘、文字编辑、人像、视角、标注、透明背景、图层、全景或素材操作时，先读 [图片工具与 MCP](references/image-toolbar-tools.md)。按具体动作检查模型能力；本地工具直接处理实际资源，AI 编辑短提交后查询真实任务并验收，不把工具已注册等同于上游已验证。

操作绘图内部、导演场景/CAM 或时间线之前，读取 [专用编辑](references/specialized-editing.md) 中对应段落，使用其绘图 revision、sceneHash 或 timeline expectedHash，不加载无关模块。
