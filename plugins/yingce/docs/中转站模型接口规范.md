# 视频模型目录与参数验证

更新日期：2026-10-08。

## 新模型的自动导入顺序

1. 读取中转站现有 `/models` 目录，优先使用该渠道实际声明的分辨率、画幅、时长和默认值。
2. 接受 snake_case、camelCase、根级列表、字符串/数字列表和 `enum` 包装。空列表、`null` 或错误类型视为未提供声明，不能让模型选择界面崩溃。
3. 未声明分辨率时，使用已记录来源的型号规则；未知私有工作流显示“渠道默认”。型号推断不能视为这个渠道已支持该档位。
4. 新模型初始化所声明的选项。刷新已有模型仅补缺失信息，保留人工调整、明确拒绝证据、模型身份、协议和已采用媒体。实际渠道声明可替换未修改的型号推断；人工改过的档位保持不变。
5. 视频设置始终有可见的分辨率入口。未公开参数的模型不能凭名称保证具体像素尺寸。

## 中转站推荐声明

下例是 OpenAI 风格模型目录上的扩展元数据示例，不代表所有中转站都已经提供这些扩展，也不代表该示例模型已经实测。

```json
{
  "object": "list",
  "data": [
    {
      "id": "example-video-v1",
      "model_type": "video",
      "supported_endpoint_types": ["openai-video"],
      "default_parameters": {
        "aspect_ratio": "16:9",
        "resolution": "720P",
        "seconds": 5
      },
      "options": {
        "aspect_ratio": ["16:9", "9:16"],
        "resolution": ["720P", "1080P"],
        "seconds": [5, 10]
      }
    }
  ]
}
```

也可使用 `supported_resolutions`、`supported_aspect_ratios`、`supported_durations` 及相应 camelCase 字段。声明值必须与实际生成接口、该模型版本和当前渠道的转发规则一致。

## 请求映射

- 保留用户选中的逻辑画幅和分辨率，用它们进行能力校验。OpenAI 视频兼容协议的 `size` 在发送时转换为像素尺寸，例如 16:9 / 2K 对应 `2560x1440`。
- 别把这个映射施加到所有协议。其他供应商的分辨率枚举、画幅字段和尺寸字段依照其已实现的接口适配。
- Axon 的已识别 H3 入口另带 `aspect_ratio` 和 `resolution_name`。这些字段是此适配的请求字段，不能推断任意供应商都接受它们；仍需以实际输出核对。
- 中转站应将声明的选项映射到上游实际参数。无法支持的值应明确返回参数错误，不能默默忽略后仍宣称按所选参数完成。
- 中转站最好返回实际输出宽、高和所采用的参数，以便区别请求设置与生成结果。目录未公开的能力，软件无法保证自动识别。

## 实测与证据

1. 复用真实任务和资源，先核对实际请求字段，再完整解码返回的视频。
2. 比较请求画幅、分辨率与输出像素尺寸；容许已定义的少量原生尺寸填充，但不允许横屏变竖屏或低清结果冒充高档位。
3. 软件在当前直接系统渠道的视频任务完成时记录非敏感的参数证据；完整资源探测可通过同一用户的原始提交日志补全完成后已过滤的参数记录。逻辑模型路由需要按实际选中的供应线路另行关联，不能归到原始模型上。
4. 证据包含真实 taskId、resourceId、能力版本、请求档位、实际尺寸和完整解码状态。不得保存 API Key；管理员并发修改的模型配置不能被旧证据覆盖。
5. “已实测”与“支持通过”分开。实际测试后可以移除“尚未实测”，但参数不一致必须显示实测不一致；不能写成已支持。完整解码不代表画面、声音或口型质量合格。
6. 参数不一致不触发重复付费、删除档位、换掉已采用视频或伪造通过。旧视频的再次探测不能覆盖更近期的测试结论。

## 排查中转站与上游

先记录软件发送的逻辑分辨率、画幅、协议像素尺寸，再核对中转站实际
映射到上游的字段和返回媒体的真实像素。仅凭播放器观感不能判断输出
分辨率；参数名正确也不能证明中转站已读取该参数。

中转站旧插件若只识别少数像素尺寸，可能把新档位静默替换为默认值。
修复应统一请求与计费的参数解释，识别真实声明的别名，显式拒绝未知
值，并以真实输出验证。不能为未知型号盲套 H3 档位或伪造通过。

运行证据和服务端备份由使用者保存在受限目录，禁止连同源码发布。
