# 画布 MCP 与规则优化记录

本文记录可复用的画布控制规则；具体运行版本以当前安装和真实工具发现结果为准。

## 本次完成

| 问题 | 已做的修改 | 作用范围 |
| --- | --- | --- |

摘要模式减少的是返回给模型的全图文本，不是上游生成费用，也没有改变画布数据。它省略节点/连线/资源明细，不能被当作这些内容为空。更新长提示词前仍要精确读取目标节点。

## 整理后的控制规则

1. 明确 canvasId、节点 ID、rowId 和采用 resourceId；同画布多标签的写入仍按原有机制拒绝，不绕过歧义检查。
2. 新状态前置条件 → 针对目标写入 → 回读实际结果。修改串行执行；独立读取可并行。冲突后重新计算修改，不盲目套用旧输入。
3. 真实绑定、可见连线、参考顺序和内联智能 `@` 一致；纯文字名称不证明媒体发送成功。长提示词直接放目标生成框。
4. 本镜使用独立切图；前镜末格只传状态，下镜动作继续推进。六图方案属于当前片子，其他模型按实际能力。确认 MiniMax H3 时才加载官方 H3 技能。
5. 超时、断连和无回执不等于生成失败。先查原任务/操作 ID；明确失败且已有授权才建立带 retryOf 的新尝试，并记录具体纠正要求。
6. 局部布局、逐张切图可见、顺序标题明确；清理前核对采用资源、下游引用和运行任务。撤销使用原生 Agent 历史。
7. 提交、生成成功、持久化、解码和质量验收分别记录。未审看/听审不声称质量通过。

## 布局语义核对

实际页面实现已支持：明确 ids 作用于指定范围；`ids=[]` 明确为全图；省略 ids 使用选区，没有选区时为全图。当前会话里的旧工具说明仍落后于源代码，本次统一了新工具描述与技能。Frame 的子节点可能随父容器调整，不能只按顶层选区估计全部影响。

## 部署与当前限制

- Canvas Agent TypeScript 编译成功，生成文件已写入本包 `canvas-agent/dist`。本次未运行软件测试，也未触发生成或修改任何制作画布/采用媒体。
- 检查时 MCP 的 diagnostics/list/capabilities 全部返回 fetch failed，本机3000、8080、17371没有监听服务，因此没有进行在线画布操作联调。
- 已运行的 MCP 进程和已读的会话不会自动更新工具列表/初始化说明。下次启动本便携包并重新连接 MCP、使用新会话后加载新版本；未声称本会话已热更新。
- Codex 缓存与迁移包中的四项控制技能、专用编辑参考已同步。本机自定义技能目录没有这些同名控制技能，未创建重复副本。
- 原件保存在本目录 `backup/`，没有删除用户素材或历史任务。迁移 ZIP 仍是规则与工程元信息包，不包含完整软件及原媒体。

## 可继续优化的接口

1. 当前写入结果有些携带整份 snapshot；后续可增加兼容的简要回执，进一步减少大型画布工具结果。
2. 通用节点更新不提供所有配置的专用强类型字段；可按真实使用需要逐项增加，避免把任意 metadata 当成页面操作。
3. 当前同一画布多标签采用拒绝写入策略；如需并行编辑，应先设计统一版本与写入协调，不能直接放开 clientId 限制。

这些扩展本次未实现；无需为本次优化重生成已经验收的图片或视频。
